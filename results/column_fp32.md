# 第二阶段：FP32 Column-SWTCF

## 实现范围与实验条件

实现通用 `Y=AX`：任意矩形稀疏 A、实际正负 FP32 权重、FP32 X/Y、TF32 Tensor Core 乘加。C0/C1/C2/C3 可以独立选择。未加入全局重排、局部度数排序、TC–CC 分流、量化或性能模型。

性能实验：单张 RTX 5090（GPU 0，32 GB），驱动 580.105.08，CUDA 12.8.93，sm_120，2026-10-12。默认 SW_SIZE=16、CACHE_SIZE=32、F_TILE=128，每 CTA 4 Warp。另一张 5090 仅用于独立参数配置的正确性验证，不参与下表计时。

Row 的一个必要修复：racecheck 检测到初始 X 加载时的行映射跨 Warp 竞争；在进入主循环前增加一次 `__syncthreads()`，避免快 Warp 的下一映射预取覆盖慢 Warp 正在读取的映射。共享内存异步 PTX 辅助函数补充编译器 memory clobber。没有改变 Row 任务划分、MMA 顺序或 Tile 流水线。修复前诊断见 [row_mapping_race_before_fix.txt](row_mapping_race_before_fix.txt)。原始 Acc 源码完全未改。本报告 Row 数值为修复后重新实测，历史 `row_fp32.md` 保留，不能直接视作本阶段固定数值。

测试中还修复了 pageable H2D 传输与非默认 Stream 的时序问题：上传构造器明确等待默认 Stream 完成，之后才在 nonblocking Stream 启动计算。此等待在算子计时之外。

## 数据格式

Column Converter 接收 CanonicalCSR。先按源列/8 将 CSR 元素分桶；保持目标行、局部列升序；每 8 个有效输出行形成 Tile。SW 行映射升序，缓存选择按跨 CW 出现次数降序，次数相同按原始行号升序。缓存选择只决定槽位，不改变 Tile 处理顺序。

| 字段 | 内容 |
| --- | --- |
| rows / cols / superWindowSize | 矩阵尺寸及 SW 宽度 |
| colWindowOffset | 每 CW 的 Tile 起止范围 |
| tileLocalBit | 8×8 bitmap，bit=8r+c |
| tileRowSlot | 每 Tile 八个 SW 局部目标行槽；尾部 UINT32_MAX |
| tileValueOffset / values | 按置位 bit 升序存储实际 FP32 权重 |
| superWindowRowOffset / superWindowRows | 每 SW 的实际目标行映射 |
| superWindowRowCacheSlot | SW 行槽到缓存槽，UINT32_MAX 表示不缓存 |
| superWindowCachedRowSlot / superWindowCachedCount | 每 SW 的固定容量逆映射及有效缓存数 |

所有存储索引为 uint32。转换中对累计非零数、Tile 数、行槽数量、SW 行映射数量、缓存映射容量进行检查，溢出时报错。重复坐标由 canonicalCSR 求和，抵消为零的项移除；convertColumn 拒绝未规范化 CSR。完全空矩阵、空 CW/SW、尾列与尾 Tile 均保留正确偏移。

`convertColumn` 为 CPU 离线转换。独立解码器按 bitmap 位逐项重建坐标和权重，与 CanonicalCSR 精确比较；真实图同样执行解码验证。

## MMA 与线程映射

计算转置形式 `X_w^T A_t^T = Y_t^T`，复用 Acc 的 `mma.sync.aligned.m16n8k8.row.col.f32.tf32.tf32.f32` 和 `cvt.rna.tf32.f32`。每 Warp 处理 32 个特征，每 Tile 两次 MMA；128 个特征由四个 Warp 覆盖。

令 lane 的 `g=lane/4`、`k=lane%4`，Warp 的特征起点为 f：

- 第一操作数四寄存器：X[8w+k,f+g]、X[8w+k,f+g+8]、X[8w+k+4,f+g]、X[8w+k+4,f+g+8]；第二次 MMA 特征位置加 16。
- 第二操作数两寄存器：A_t[g,k]、A_t[g,k+4]，对应稀疏 Tile 的转置片段。
- 四个输出寄存器 i=0..3：目标行位置 `2k+(i%2)`，特征 `f+g+(i>=2 ? 8 : 0)`；第二次 MMA 加 16。

对应 X 在一个 CW 内只加载一次，所有 Tile 复用寄存器片段。尾源列和尾特征加载置零，输出只更新有效目标行和有效特征。稀疏零位不访问 values；置位位置通过低位 popcount 找到压缩权重。

SASS 检查确认四个版本均包含 `HMMA.1688.F32.TF32`，C1/C2/C3 包含异步 `LDGSTS`，没有用逐边 CUDA Core 乘法代替 MMA。静态指令检查见 [column_sass.txt](column_sass.txt)，这些静态指令位置数不代表硬件动态计数。

## 四个版本与同步

| 版本 | 任务划分 | 数据准备 | 输出 |
| --- | --- | --- | --- |
| C0 | CW × 128 特征 | 同步加载一个稀疏 Tile，X 在寄存器复用 | 全局 atomicAdd |
| C1 | 与 C0 相同 | 稀疏 A/行映射两份共享缓冲；预取下一 Tile | 与 C0 相同 |
| C2 | SW × 128 特征 | C1 流水线；在最后一个 Tile 提前加载下一 CW 的 X | 全局 atomicAdd |
| C3 | 与 C2 相同 | 与 C2 相同 | 重复行累加到 shared cache，SW 结束时统一 atomicAdd |

C1 在当前 Tile MMA 前向另一缓冲发出下一 Tile 的权重/行槽 cp.async 并 commit；执行当前 MMA 和输出更新后 wait_group 0，再 CTA 同步。不同缓冲保证预取不覆盖当前片段，末尾同步保证所有 Warp 完成读取后才能再次使用缓冲。这提供真实的预取/MMA 重叠机会，实际收益通过 C0/C1 对照衡量。

C2/C3 使用单一 Warp Group：四个 Warp 各自拥有不同的特征位置，同一个 CW 的一个目标行只在一个 Tile 内出现，每个缓存元素在一次 Tile 更新中只有一个 lane 写入。Tile 间 CTA 同步，跨 CW 顺序执行，因此共享缓存不需要 shared atomic，也不需要多组独立副本。结束时统一同步并写回，每个缓存行/有效特征一次 global atomic。不同 SW/特征任务间仍使用全局 atomicAdd。

共享缓存最大 32×128×4=16384 B，加两份 A/行映射缓冲共 16960 B。C2/C3 的 Tile 顺序、特征块和线程组织一致。C2 即关闭缓存的 SW 对照。

## 公平计时方法

所有方法共享同一个 CanonicalCSR、同一个 GPU X、相同 F、同一 GPU。图来自本地准备的 ogbn-arxiv / ogbn-products，均已经去重并包含反向边/自环；本阶段不再修改图语义，A 的所有非零权重为 1。实际节点 FP32 特征被复用：F 小于原维度时截取，超过原维度时循环扩展，arxiv 原维度 128，Products 原维度 100。扩展维度是 SpMM 基准输入，不是模型精度实验。

区域为连续 4096 个原始目标行；区域内源列按原编号升序压缩，X 做同样映射。这是形成矩形区域子矩阵的局部索引处理，整个图不进行全局重排，也没有度数排序。不同方法使用完全相同的区域输入。

- 转换：CPU wall time，分别报告 Row/Column；不含图文件读取、CSR 规范化和解码检查。
- 格式上传：同步完成的 wall time，包括 GPU 格式数组分配与 H2D，不包含 X/Y 分配和特征上传。
- Row：直接写完整 Y，无需清零。
- Column complete：每次 `memset(Y)+kernel`，CUDA Graph 中每次独立 SpMM 都含清零；预热 10 次，五组 Graph/Event 批次中位数。
- Column isolated kernel：同样每次先清零，但用捕获进 Graph 的 external CUDA timing events 只包围 Kernel，五组中位数。
- Column clear：单独测试 memset 的 Graph/Event 中位数。isolated/clear/complete 是不同测量序列，不能要求三个中位数精确相加。
- 完整 arxiv 和区域每组 30 次，完整 Products 每组 20 次。当前采用一次进程内五组样本；未进行跨日期重复实验或固定 GPU 时钟。
- 性能比较使用 complete SpMM，不用不清零的连续原子累加冒充独立调用。

## 当前瓶颈与结论

- arxiv 全图，F=128：最快 Column 为 C1（2.02303 ms），Row 为 1.19299 ms；Row/Column=0.590。
- arxiv 区域 0，F=128：最快 Column 为 C2（0.06380 ms），Row 为 0.66134 ms；Row/Column=10.366。
- arxiv 区域 165247，F=128：最快 Column 为 C1（0.05498 ms），Row 为 0.18599 ms；Row/Column=3.383。
- Products 全图，F=128：最快 Column 为 C3（106.95559 ms），Row 为 30.95803 ms；Row/Column=0.289。
- Products 区域 0，F=128：最快 Column 为 C0（0.28457 ms），Row 为 0.57079 ms；Row/Column=2.006。
- Products 区域 1047828，F=128：最快 Column 为 C0（0.06730 ms），Row 为 0.08207 ms；Row/Column=1.219。
- Products 区域 2444933，F=128：最快 Column 为 C0（0.08943 ms），Row 为 0.35703 ms；Row/Column=3.992。

完整图上 Column Tile 密度约 0.12，填零 MMA 工作较多；CW Tile 数量跨度大，SW 合并可能加重任务长尾。Column 大量散布输出原子更新，F 越大更新数越高；输入 X 复用不能消除输出代价。Column 元数据和存储量也高于 Row。

C3 将 shared 增至 16960 B，可驻留 CTA 从 C2 的 9 降至 5，并增加行槽查询及缓存读写。缓存行跨度为 128 个 float，不同行的同一特征映射到相同 shared memory bank；多个 lane 同时更新不同缓存行时可能产生 bank conflict，实际开销尚未由硬件计数确认。它仅缓存 32 行，整体更新数减少有限；但热行的更新争用可能影响关键路径，因此少量更新减少也可能对应局部性能收益。当前结论来自版本对照和结构统计，具体带宽、争用和计算占比仍需有计数器权限的 profiling 确认。

流水线、SW、缓存都没有保证普遍提速，保留所有负面结果；最快版本按每个案例实测记录，本阶段不实现自动选择。C2 对 C1 的对照包含 SW 任务组织及下一 CW 的 X 预取，不能解释为单一布局因素的纯收益。

非常接近的耗时不代表显著收益，例如完整 Products 的 F=32 中 C0/C1 基本相同。表格保留中位数，但尚无跨进程重复实验和置信区间。CPU 离线转换及上传也明显高于单次 Kernel 时间，本报告不宣称这些 Kernel 对完整 GNN 训练的端到端加速。
